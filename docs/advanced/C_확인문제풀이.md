## 1장

1. 경로가 `…\olist\\olist_orders_dataset.csv` 처럼 `\` 가 두 번 들어간다. Windows 는 대개 그래도 파일을 찾지만, 헷갈리고 다른 프로그램에서는 오류가 날 수 있으니 매개 변수 값 끝에는 `\` 를 붙이지 않는 규칙을 정해 두자.
2. **98,666**. 개수는 112,650. 주문 하나에 상품이 여러 개면 같은 order_id 가 여러 줄에 나오므로, 서로 다른 값의 수(개수(고유))는 행 수보다 적다.
3. **큰따옴표(")** 로 감싸여 있다. 따옴표 안의 줄 바꿈은 값의 일부인데, 기본 설정(QuoteStyle.None)은 이것을 행의 끝으로 읽는다.

## 2장

1. 달라지지 않는다(**99,441**). 주문의 customer_id 는 모두 고객 파일에 있다. 왼쪽 앤티 조인으로 병합하면 **0행** 이 나온다.
2. **늘어난다** (6,535 → 7,827). 예상배송일 **당일**에 도착한 주문까지 지연으로 센다. "예상일까지 오면 정시" 라는 뜻으로 `>` 를 쓴다. 이렇게 **정의**가 결과를 바꾸므로 보고서에 기준을 적어 두자.
3. **3건**. 원래 값은 `not_defined` (결제 방식이 기록되지 않음).

## 3장

1. 주 → 주문 은 **일(1) → 다(\*)** 방향이라 필터가 바로 흐른다. 주문수·고객수는 주문 테이블에서 세므로 지역마다 다르게 나온다. 대분류는 상품 → 주문상품 → (거꾸로) 주문 이어서 막혔다.
2. 모든 행이 **96,096** 으로 같다. 판매자 → 주문상품 까지만 필터가 흐르고, 고객ID 가 있는 주문 테이블은 걸러지지 않는다.
3. **점선(비활성)**. 날짜와 주문 사이에 이미 활성 관계(구매일)가 있기 때문이다.
4. **68,266건, 68.65%**. 주문 3건 중 2건이 남동부 고객이다.

## 4장

1. **625**.
2. 분모 `CALCULATE([상품매출], REMOVEFILTERS('상품'))` 는 **상품** 필터만 없앤다. 지역 필터(주 테이블)는 그대로 남아 분모도 그 지역 매출이 되므로 100%. 지역별 비중은 `REMOVEFILTERS('주')` 로 바꿔야 한다. 비중 측정값은 **어떤 테이블의 필터를 없앨지**를 행에 놓을 필드에 맞춰 정한다.
3. 가장 낮은 것은 **기타 3.91**, 그다음 가구·인테리어 3.95. 가장 높은 것은 **도서·음반·문구 4.28**.
